# Factor — Атомарная база фактов

> Модуль зафиксирован: 2026-07-18
> Статус: концепция, в беклоге

---

## Идеология

Не заметки (Eventor), не документы (Booker), не вещи (Stuffer), не люди (Contactor).

**Factor — это то, что ты знаешь и не должен гуглить.**

VIN машины. Внутренний диаметр уплотнителя — 43мм. Имя архитектора с которым познакомился на конфе. Артикул фильтра. Номер договора аренды.

Атомарные факты о мире вокруг тебя. Killer feature — поиск за 2 секунды с мобилки.

---

## Откуда боль

- VIN → где-то в переписке Авито
- Диаметр резинки → вспомнили в Eventor, а нужно было в магазине
- Адрес офиса → "погугли сейчас"
- Имя разраба с конференции → "как-то на -ов заканчивается"

Факты живут в мессенджерах, заметках, памяти — и не находятся в нужный момент.

---

## Название

**Factor** — выбрано осознанно.

- "Фактор" как в "факт" — буквально зашито
- "Решающий фактор" — вес информации
- Совдеповский контекст: "Фактор Икс" — якорь в памяти, запоминается
- Паттерн -or как у всех модулей Teftele: Eventor, Contactor, Exploiter

## Схема БД

```sql
fct_facts
├── id              ULID(26)          PK
├── user_id         ULID              FK → users
├── label           varchar(255)      "VIN BMW E90"
├── value           text              "WBA3G510X0NS47291"
├── context         text | null       "из объявления Авито, июль 2024"
├── kind            enum              document | technical | professional | personal | other
├── valid_from      date | null       ← факт начал действовать
├── valid_to        date | null       ← факт устарел (старый адрес, проданная машина)
├── is_pinned       tinyint(1)        быстрый доступ
├── sort_order      int
├── created_at      timestamp
└── updated_at      timestamp

fct_tags                              ← отдельная таблица тегов (своя, не общая)
└── fact_id + tag_id

fct_fact_tags
├── fact_id         FK → fct_facts
└── tag             varchar(64)       ← денормализация, без отдельной таблицы тегов
```

> Теги скорее всего просто строки в JSON array — факты не требуют сложной таксономии.

## Satellite Pattern — линковка

По стандартному satellite-паттерну Teftele: **FK живёт на satellite-стороне**, Factor не знает о других модулях.

```
stf_things.factor_fact_id        ← VIN, артикул, тех. параметры вещи
cnt_contacts.factor_fact_id      ← факты о человеке (должность, компания точно)
stf_register.factor_fact_id      ← факт всплывший при событии
led_transactions.factor_fact_id  ← номер договора, счёта
evt_events.factor_fact_id        ← факт зафиксированный в событии
```

Factor сам хранит только `fct_facts`. Связи — снаружи.

## Природа данных — три слоя про одну вещь

Пример: BMW E90

| Слой | Модуль | Пример |
|------|--------|--------|
| **Действие** | Stuffer / Exploiter | заменил масло, сломалась подвеска |
| **Информация** | Eventor | исследовал стук, читал форум, подозреваю рычаги |
| **Факт** | Factor | VIN: WBA..., диаметр сальника: 43мм, масло: 5W-40 |

Все три про одну машину — разная природа, разный UX.

В UI страницы вещи в Exploiter → три секции, не одна.

## UX — главное

### Поиск
- Открыл Factor → фокус сразу в поиске
- Набрал "VIN" → мгновенный результат (без Enter)
- Скопировал → пошёл дальше

### Capture (мобилка)
- FAB-кнопка → два поля: label + value → сохранил за 5 секунд
- context и kind — опционально, потом допишу

### Карточка факта
```
┌─────────────────────────────────┐
│ VIN BMW E90          [document] │
│ WBA3G510X0NS47291               │
│ из объявления Авито, июль 2024  │
│                      [📋] [✏️] │
└─────────────────────────────────┘
```

- Одна кнопка — скопировать value в буфер
- valid_to заполнен → карточка серая (факт устарел)

### Группировка
По kind или по тегам. Pinned факты — наверху всегда.

## kind — значения

| Значение | Смысл | Пример |
|----------|-------|--------|
| `document` | Документы и их номера | VIN, СНИЛС, номер договора |
| `technical` | Тех. параметры | диаметр 43мм, артикул XYZ, модель контроллера |
| `professional` | Профессиональный контекст | имена людей, компании, стеки, технологии |
| `personal` | Личная фактология | адреса, телефоны, даты |
| `other` | Всё остальное | — |

```

Factor ←── Exploiter  (параметры активов)
```
